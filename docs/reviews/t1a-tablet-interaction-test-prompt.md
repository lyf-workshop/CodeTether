## 目标

功能已经验收过了。这轮看的是**用起来顺不顺**：常做的事要几步、哪里要猜、哪里容易点错、出错时知不知道怎么办。

**A. 常做的事**（09 §1 的 T1 到 T8，直连和经互联网连接各至少走一遍）。每件事记：

- 实际的步骤（每一次点击、输入、滑动都算一步），和 09 §2 推出来的路径比，哪里不一样；
- 从开始到完成的时间；
- 哪一步要停下来想、点错、回头，截图。

**B. 交互细节**：

- 系统返回手势：在每一层（侧栏、弹窗、变更面板、会话、设置子页）按返回，退到的地方对不对，会不会一下子退出应用；
- 滚动：长会话快速滑动是否流畅；往上翻读的时候来了新消息，位置会不会被拉走，有没有"回到最新"（09 的 P8）；离开再回来，列表和会话的位置还在不在；
- 输入法：输入框被键盘挡住没有；发送后键盘和焦点怎么样；中文输入法组字时按回车会不会误发；
- 选中和复制：消息、批准卡里的命令、diff 能不能长按选中复制（P7）；
- 连点：快速连点"发送""允许一次""开始""处理完成"，只执行一次；
- 状态和反馈：每个操作点下去以后多久有反应（按钮变化、转圈、提示）；读取中、空列表、离线、慢网（用系统开发者选项或断开再连 Wi‑Fi 制造）、出错时各显示什么，提示是不是说清了发生了什么、怎么办；
- 新建会话（P2）：分别从首页、项目页、设备页、侧栏项目行打开，项目是不是已经选好；第一条消息写三四行时看不看得全；
- 停止（P5）：停止按钮离别的按钮多近，手掌或手指误触的可能性；
- 搜索（P6）：搜一个没打开过的旧会话标题，结果和提示是什么。

**C. 无障碍**：

- 打开 TalkBack，走一遍 T2 和 T3：只有图标的按钮（侧栏开关、变更、更多、关闭）有没有读出名字；
- 系统字体调到最大、显示大小调大：文字有没有被截断、重叠，按钮还能不能点；
- 点击区域：用布局检查（`uiautomator dump` 或 Layout Inspector）找出小于 48dp 的可点击元素；
- 深色模式下文字和背景是否看得清。

**D. 长内容和数量多**：

- 长标题、长项目名、长路径、长命令、很长的一行代码、很大的 diff（几百行）、很长的会话（几百条消息）、很多台设备和项目（侧栏能不能用）；
- 真机上用真实数据能造的就造；造不出来的（比如很多台设备），在专用模拟器 `codetether_t1a_pixel_tablet_api36` 上用合成数据测，并注明。

**E. 复验项**（原 `device-recheck-prompt.md` 的平板部分）：

- 生产 Relay 已更新到 `e4bdd57`：强制只经互联网连接（Debug 构建里的选项"只经互联网连接"），新建会话 5 次，每次电脑上恰好多一个会话、第一条消息只发一次、没有停在"结果待确认"；
- 进程被系统回收：会话打开、变更面板开着、选中一个文件、输入框里有草稿，把应用放到后台，`adb shell am kill org.codetether.app`，再从最近任务回来，这些都还在；
- 被移除页和文案：在 Windows 上移除平板，首页顶部红色告警条、侧栏还在、两个操作；界面上找不到 Host、Node、Machine、Supervisor、Relay、授权、指纹这些词（Debug 的诊断选项除外）；再用新码配一次。

**F. 用户本人试用 15 分钟**：

- A 到 E 做完以后，停下来请用户在平板上做下面 6 件事，用 `adb shell screenrecord` 录屏并计时，用户做的时候你不提示：
  1. 找到正在等批准的会话，看清要运行什么命令，批准它；
  2. 打开一个改过文件的会话，把改动从头到尾读一遍，再追加一句"再加一个测试"；
  3. 在测试项目里新建一个 Codex 会话，问一个问题；
  4. 让一个任务跑起来，然后停掉它；
  5. 找到昨天或更早的一个会话；
  6. 竖过来再横过来，接着刚才的事做。
- 做完问用户 5 个问题，原话记下来：哪一件最费劲；有没有哪一步不知道该点哪里；有没有点错过；最想改的一处；整体用着和电脑上比怎么样。
