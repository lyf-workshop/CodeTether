# 03 · 项目规划（电脑 · 平板 · 手机）

日期：2026-10-19。依据：已验收基线 `bbcda69`、v4 设计（`34b8ee5`）、`ux/v4-device-first` 上已完成的 v4 前端实现（`df91601`，未审核）、docs/PRODUCT.md 与 docs/ROADMAP.md。

## 1. 产品预期

- 电脑是工作台：AI 工具在电脑上运行，项目、会话、配置都在这里。
- 手机最重要的是随时和 AI 工具对话（新建会话、回复，输入框要完整），其次是推送提醒和批准、停止。平板是阅读和审阅的屏幕，也能新建和回复。两者是原生应用，登录同一账号来查看和控制你的电脑，自己不运行 AI 工具，也不出现在“设备”列表里；关闭手机应用不会停止电脑上的工作。
- 详细需求以 04-requirements.md 为准。
- 结构始终是 账号 › 设备 › 项目 › 会话。一个项目就是一台设备上的一个文件夹。

| 功能 | 电脑 | 平板 | 手机 |
|---|---|---|---|
| 最近会话（所有设备和项目） | 侧栏设备树 | ✓ | ✓ 首页 |
| 对话、回复（完整输入框） | ✓ | ✓ | ✓ |
| 新建会话（已有项目里） | ✓ | ✓ | ✓ |
| 待处理（批准 / 完成 / 失败） | ✓ | ✓ | ✓ |
| 批准 / 拒绝、停止 | ✓ | ✓ | ✓（先解锁） |
| 浏览 设备 › 项目 › 会话 | ✓ | ✓ | ✓ 按设备分组 |
| 变更 | ✓ 逐行 | ✓ 逐行 | 只看摘要 |
| 项目内搜索 | ✓ | ✓ | — |
| 添加项目、导入以前的会话、添加设备 / 配对 | ✓ | — | — |
| 设置 / 诊断 / 首次启动 | ✓ | — | 账号、通知、解锁确认 |
| 通知 | 系统通知（已有） | 推送 | 推送 |

## 2. 现状（在代码里核实）

- 电脑端：v4 已在 Windows 和 Mac 上验收通过（各 15/15），合入 `main` 并发布为 `v0.1.0-alpha.2`（`0f624ae`），审核记录在 `docs/reviews/ux-v4-device-first.md`。
- 远程访问（Supervisor 传输，`packages/supervisor-transport`）：TLS 1.3 + Host 固定 + ProductDevice 证明，直连或经 Relay。
  - 只有 12 个操作：`host.bootstrap`、`machine.list/get`、`project.list/get`、`conversation.list/get/history/live.read`、`action.get`、`conversation.create`、`conversation.turn.start`。
  - **没有** 待处理列表、批准 / 拒绝、停止。
- 权限：协议有 `supervisor_read` 和 `supervisor_control`。账号服务只签发 read；control 有 Host 表和 `/api/v1/supervisor/control/approve`，但没有界面调用，出厂不可达。
- 后端阶段（2026-11-02 B0 部署后）：Control Plane 运行 `main` `454f414`，迁移到 0008；公网 Relay 在 `tls://relay.codetether.org:8443`（`relay_d41fc913a6e74e65b916467b97bc299b`，证书 2027-01-01 到期，需要人工续期后重启）；Windows Host 的 Relay presence 在线。经 Relay 的七项只读读取还没做：Windows 和 Mac 现有的只读授权都已过期，v4 界面没有申请入口，你决定先放着。报告在 `agenthub-archive/b0-report.md`。ROADMAP 里旧的 Mobile Supervisor（9B）已标为被 M 系列取代。
- 没有推送（APNs / FCM），没有手机或平板客户端。
- 能力限制会一直带到手机端：停止、审批、变更只支持电脑本机上的 Codex；Claude Code 只读取和搜索。

## 3. 分工

每个阶段都走同一个流程：

1. 我做设计：原型、截图、交接文档，后端阶段写接口和数据说明。
2. 你确认设计。
3. 我写给编码智能体的提示词。
4. 编码智能体在单独的分支和工作区里实现，按任务需要提交、推送、部署和安装。
5. 我审核：读 diff，跑 typecheck / lint / test / build，对照设计和本文 §6 的不变量，写审核报告；有问题就写修复提示词，再审一轮。
6. 你在真机上验收，然后合并、发布。

需要你本人的：Apple 开发者账号和 Google Play 账号、签名证书和更新签名私钥、商店上架，以及最后的真机验收。部署 Control Plane、Relay 和更新文件、安装新版本，都可以交给智能体（2026-11-02 你的决定）。

## 5. 原生应用的技术方案（M0 前需要你定）

难点不在界面，而在连接：手机必须实现和电脑一样的 Supervisor 客户端（TLS 1.3、Host 固定、绑定 TLS 导出密钥的设备证明、Relay 帧协议）。现在这个客户端是 Node 的 TypeScript，手机上不能直接用。

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | SwiftUI（iPhone / iPad）+ Jetpack Compose（Android），共享一个 Rust 核心（rustls + Supervisor / Relay 协议，UniFFI 生成 Swift 和 Kotlin 接口） | 界面最原生；安全协议只实现一次；Rust 和现有 Tauri 同一语言 | 两套界面代码 |
| B | Tauri 2 移动端，复用现有 React 界面 + Rust 核心 | 代码最少 | 体验接近网页，和“原生应用”的目标不一致 |
| C | 只做 iOS / iPadOS，Swift 实现客户端 | 最快出第一版 | Android 以后要重写一遍协议 |

已定（2026-10-19）：**先做 Android 手机和平板**，iOS / iPadOS 以后再做。原因：
- Android 在自己手机上安装调试不需要付费（开 USB 调试，用 adb 或 Android Studio 安装）；只有上架 Google Play 需要一次性的开发者注册费。推送不用 FCM，走自己的连接（B2）。
- vivo（OriginOS）、小米（HyperOS）、OPPO（ColorOS）、荣耀都是 Android，可以直接安装 APK；华为 HarmonyOS 5 / NEXT 不能运行 APK。国内品牌后台清理比较激进，要在手机设置里放行（M3 引导）。
- iOS 不加入 Apple Developer Program 也能用免费 Apple ID 在自己的 iPhone 上调试，但需要一台 Mac + Xcode，安装的应用 7 天后失效要重装，而且免费账号不能使用推送通知。推送是手机端的核心功能，所以 iOS 实际要等付费会员（99 美元 / 年）。

因此方案 A 调整为：Android 用 Kotlin + Jetpack Compose，手机和平板是同一个应用、两套布局；连接核心仍用 Rust（UniFFI 生成 Kotlin 接口），以后做 iOS 时直接复用。如果 M0 发现 Rust 核心在 Android 上的成本过高，再评估纯 Kotlin（Conscrypt 支持 TLS 1.3 和导出密钥）。设备私钥放 Android Keystore，优先 StrongBox。

## 6. 每个阶段都要守住的不变量（审核清单）

- 账号、ProductDevice、Host、Relay、Machine 的身份和信任彼此独立，一种不能换成另一种。
- 手机和平板只通过 Supervisor 访问电脑，不直接连本机 4317 端口。
- 配对只能用电脑界面上生成的配对码，control 权限也只能在这里选，本机其他程序不能绕过界面授予；配对码 5 分钟有效、只能用一次、输错 5 次作废；可以移除，移除后立刻断开；read 和 control 分开。
- 手机和平板应用停止、断网、退出登录都不影响电脑上正在运行的工作；只有“停止”会停止。
- 远程操作沿用本机门控：`actionId` 幂等，运行中不能归档，失败后不自动重发，忙碌时返回 409，审批和停止只对支持的 AI 工具开放。
- 推送和系统通知都不含会话标题、提示词、命令和路径；锁屏上只显示类型和数量；通知上不能直接批准。推送不经过第三方推送服务。
- 界面只显示后端真实提供的能力；还没做的只出现在后续规划。
- 凭据和密钥（`.secrets/`、私钥、连接串）不打印，也不进仓库和报告。
- 部署和替换安装版之前先备份（数据库先备份），并写清怎么回退。us-vps-01 上还有官网和其他项目，删数据或可能影响它们的操作先和你确认。
