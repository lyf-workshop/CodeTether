本文件记录桌面预览中已确认的问题、修改和验收条件；各项实现与复核状态以对应条目为准。

## UX-V4-001：首次设置把“AI 服务尚未验证”表达成“工具未就绪”

- 记录日期：2026-10-19。
- 观察版本：`ux/v4-device-first`，`df91601c33e791e4d923c731a104c9136e25ea07`。
- 状态：已修复，待复核；前端模型、静态渲染与隔离浏览器布局回归已完成，尚待原生预览与真实首次执行复核。
- 场景：使用独立测试数据目录和独立 WebView 资料的 Windows 原生桌面预览。
- 用户反馈：已安装 Codex 和 Claude Code，但首次设置看起来没有检测到；普通用户不知道该如何继续。

### 已确认事实

通过正在运行的预览 Host 的公开 Doctor、设备详情响应，以及实际窗口文本确认：

| 工具                | 安装与选择       | 运行环境                         | AI 服务                  |
| ------------------- | ---------------- | -------------------------------- | ------------------------ |
| Codex 0.162.1       | 已检测到、已选择 | 可用；兼容的新版本，尚未完整验证 | 官方服务，尚未验证       |
| Claude Code 2.1.251 | 已检测到、已选择 | 可用；兼容                       | 自定义 AI 服务，尚未验证 |

两者的公开描述均为 `availability: available`，支持流式会话和原生恢复。没有发现本次安装漏检证据。

独立预览数据库没有旧版的执行成功观测，但并未清除或修改工具安装、认证或自定义 AI 服务配置。本次诊断没有调用模型，不构成 AI 服务实际连通或执行成功的证据。

### 原因与影响

1. 安装和运行环境已通过检查，但 AI 服务缺少权威验证结果，因此服务状态保持 `unknown`。这是应保留的真实性边界。
2. Doctor 的工具总体状态取到了服务的 `unknown`，前端将整张卡片的徽标显示为“尚未检查”，没有醒目说明“已安装”。
3. 首次设置使用严格的已验证就绪计数决定按钮文案，因而显示“暂不设置 AI 工具”和“至少一个 AI 工具就绪前不能运行”。
4. 正常的新建会话和输入控制实际上允许对服务未知的可用安装进行显式首次执行。上述提示容易被误解为工具漏检、必须重装或无法继续。
5. “重新检查”更新安装与运行环境等元数据，不会通过后台推理证明 AI 服务可用；反复点击不能代替实际服务验证。

该状态区分与严格就绪计数在基线已有，不能据此将问题归因于 v4 新增的安装扫描逻辑。

### 建议修改范围：仅首次设置的前端呈现

- 分开展示“安装”“运行环境”“AI 服务”三个事实。对已检测到且当前运行环境可用的工具，明确显示“已安装”和对应兼容性，不把服务未知表达成安装未检查。
- AI 服务未知时显示“尚未验证”，说明“开始首次对话时验证 AI 服务；设置过程不会发送消息或消耗模型额度”。不能将其直接标为“就绪”。
- 本次这种已安装、运行环境可用且服务仅为未知的情况，主按钮使用“继续设置”，不要使用“暂不设置 AI 工具”，也不要笼统提示“不能运行”。
- 真正缺少安装时，保留工具对应的官方安装指引和“重新检查”。
- 对已知登录要求、配置错误、服务不可用、运行环境不兼容，分别说明原因和已有的针对性操作；不能用未知状态的提示覆盖这些错误。
- 自定义 AI 服务仅因尚未验证时，不要求用户登录官方服务、切换配置或重新安装。
- 保留准确的当前／上次观测提示。设置可以继续，不等于 AI 服务已经被证明可用。

不修改 Provider 检测、选择、兼容性、Doctor 的权威状态、服务端执行门控或协议；不放宽严格的执行就绪判定。无需新增主动服务检查接口或后台推理。

### 修改前的临时使用办法（历史记录）

用户可以点击当前的“暂不设置 AI 工具”继续，添加项目并完成向导，再选择“打开 CodeTether”。之后通过正常新建会话、显式发送消息来验证服务，执行成功与否由真实结果决定。

不要求用户重装、重复登录、手动修改环境变量，或为了完成设置专门发送一条测试消息。失败时不自动重发。

### 验收条件

- [x] 两个工具已安装且服务未知时，明确展示安装成功、运行环境状态和服务尚未验证；主按钮为“继续设置”。（模型与静态渲染测试）
- [x] 仅安装其中一个工具时，可继续设置，不要求同时安装两者。（静态渲染测试）
- [x] 两个工具均未安装时，正确展示缺失及安装指引，并保留现有可跳过设置的能力。（静态渲染测试）
- [x] 服务未知不显示为故障或已验证就绪；已知登录、配置、连接和兼容性问题不被掩盖。（模型与静态渲染测试）
- [x] 自定义 AI 服务未知时，不出现强制官方登录或切换服务的指引。（静态渲染测试）
- [x] “重新检查”仍只使用已有的有界检查；打开页面及重新检查均不新增模型推理。（保留既有刷新、无推理来源断言及有界检查测试；未运行真实接口）
- [ ] 完成向导不要求测试消息；显式首次执行仍走原有安装选择、权限和执行门控，不自动重发失败消息。（前端完成屏静态渲染与严格就绪回归通过；真实首次执行未验证）
- [ ] 浅色、深色及桌面／窄屏布局的说明、按钮、键盘操作和可访问状态一致。

### 本轮浏览器复核范围

在 `pnpm dev` 的真实浏览器中，使用经现有协议形状构造的模拟 HTTP 响应，检查工具检查页和完成页的浅色／深色及 1440、1100、390 宽度，共 12 个视图。未发现横向溢出或控制台错误；服务未知时仍显示“继续设置”，完成页不带执行就绪标记。截图保存在忽略的 `output/playwright/ux-v4-review-onboarding/`。

分类为 AUTOMATED BROWSER / SIMULATED API；未连接已安装的 Desktop、真实 Host 或 AI 工具，项目创建和模型执行次数均为 0。这不是工具安装、认证或 AI 服务实际就绪的新证据；完整原生键盘／读屏和真实首次执行仍未验证，因此上述复合验收项保持未勾选。
